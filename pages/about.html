Rann

Bot Designer & Community Operator

Discord.js Node.js Python Community Ops

I'm a bot designer and community operator at Society. I don't just write code — I design bots that solve real community problems, then I run the community that uses them.

I started as a community member. Answering questions, helping newcomers, moderating chats. But I got tired of doing the same things over and over. Welcome messages, role assignments, spam cleanup. Repetitive and unscalable.

So I learned to build bots. Not to become a software engineer, but to automate the boring stuff so I could focus on what matters — the people.

Today, every bot I build starts from a real pain point I experienced firsthand. If it doesn't make the community better, it doesn't ship.

// Principles

Operating Philosophy

01 — BOTS SERVE PEOPLE

Every bot exists to make the community experience better. Not to replace human connection, but to remove friction that gets in the way.

02 — SHIP FAST, FIX FASTER

A working bot in production beats a perfect spec on paper. Deploy quickly, gather feedback, iterate.

03 — AUTOMATION + HUMAN

Bots handle the repetitive. Humans handle the meaningful. Tools amplify connection, not replace it.

04 — DESIGN FROM PAIN

Every bot starts with a real problem. No feature for feature's sake. If members don't need it, it doesn't ship.
